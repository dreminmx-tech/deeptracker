# 🔧 Технические детали

Как устроен deeptracker внутри: стек, данные, алгоритмы, PWA и тесты.
Для деплоя — [deploy.md](deploy.md).

<a id="stack"></a>

## 🧱 Стек

| Слой | Выбор | Почему так |
| --- | --- | --- |
| Сборка | **Vite 8** | мгновенный dev-сервер, статический `dist/` без рантайма |
| UI | **React 19** + TypeScript 7 (strict) | предсказуемое состояние, типы ловят опечатки в словарях |
| Состояние | React-контекст + `useState` | на таком объёме redux/zustand — лишняя зависимость |
| Хранение | `localStorage` | офлайн-first, ноль серверов, ноль аккаунтов |
| Офлайн | свой `public/sw.js` + манифест | без `vite-plugin-pwa`: меньше зависимостей, полный контроль |
| Тесты | Vitest (node-окружение) | логика в чистых модулях + `react-dom/server` для рендера |
| Иконки | свой PNG-энкодер на `zlib` | никаких `sharp`/`canvas` в зависимостях |

<a id="structure"></a>

## 🗂 Структура

```
src/
  types.ts              типы данных: Habit, Entry, DayLog, AppData, Settings
  store.tsx             контекст стора, запись в localStorage на каждое изменение
  App.tsx               оболочка: вкладки, тема, язык, ролловер суток
  styles.css            обе темы: :root (тёмная) и [data-theme='light'] (чёрно-белая)
  lib/
    date.ts             локальные ключи дат YYYY-MM-DD, недели, Intl-форматирование
    habits.ts           чистая логика: статусы, мягкие серии, агрегаты, heatmap
    actions.ts          чистые мутации: тапы, счётчики, минуты, CRUD привычек
    storage.ts          localStorage, нормализация, экспорт/импорт, скачивание файла
    i18n.ts             словари ru/en + стартовый набор привычек
    useInstallPrompt.ts хук установки PWA
    version.ts          версия приложения для настроек
  components/           TodayView, HabitsView, StatsView, SettingsView + карточка,
                        таймер, heatmap, модалка, тосты
scripts/
  make-icons.mjs        PNG-иконки и og.png (свой энкодер + растеризатор)
  smoke.mjs             проверка, что сервер и деплой отдают всю статику
```

Правило: всё в `src/lib/*` — чистые функции без React и DOM. Их тестируют напрямую, компоненты остаются тонкими.

<a id="data"></a>

## 💾 Модель данных

```ts
interface Habit {
  id: string;
  name: string;
  kind: 'check' | 'counter' | 'duration' | 'negative' | 'flex';
  target?: number;   // counter: цель в день, duration: целевые минуты
  unit?: string;     // «стаканов», «мин»
  perWeek?: number;  // flex: сколько раз в неделю
  step?: number;     // counter: шаг кнопок +/−
  tiny?: string;     // версия привычки на 2 минуты для «просто начни»
  pinned?: boolean;  // показывать в «Главном сегодня» (максимум 3)
  archived?: boolean;
  createdAt: string; // ISO; дни раньше этой даты не считаются пропусками
  order: number;     // плотный порядок 0..n-1
}

interface Entry {
  value?: number;    // counter/duration — накопленное, negative — число срывов
  done?: boolean;    // check/flex — выполнено
  note?: string;
}

interface DayLog {
  entries: Record<string, Entry>; // ключ — id привычки
  dump: DumpItem[];               // брейн-дамп на этот день
}

interface AppData {
  version: number;
  habits: Habit[];
  days: Record<string, DayLog>;   // ключ — локальная дата YYYY-MM-DD
  settings: { lang: 'ru' | 'en'; theme: 'dark' | 'light' };
}
```

Принципы:

- **Дни адресуются локальной датой** (`YYYY-MM-DD` в таймзоне пользователя), а не UTC: «сегодня» должно совпадать с календарём на стене.
- **Пустое не хранится.** Снятие галочки удаляет запись, а день без записей и без мыслей удаляется целиком — база не пухнет от пустых объектов.
- **Хронология важна.** `createdAt` отделяет «привычки ещё не было» от «привычка пропущена»: до даты создания день имеет статус `rest` и не портит статистику.

<a id="logic"></a>

## 🧠 Логика привычек

### Правила выполнения

| Тип | Выполнено когда | Значение по умолчанию |
| --- | --- | --- |
| `check` | есть запись с `done: true` | не выполнено |
| `counter` | `value >= target` | не выполнено |
| `duration` | `value >= target` (минуты) | не выполнено |
| `negative` | `value === 0` — то есть срывов нет | **выполнено** (чисто по умолчанию) |
| `flex` | есть запись с `done: true` | `rest` — день ничего не требует |

### Статус дня

`dayStatus(data, habit, key)` возвращает одно из пяти значений:

| Статус | Когда |
| --- | --- |
| `future` | дата позже сегодня |
| `rest` | день раньше `createdAt`, либо flex-привычка без записи |
| `done` | по правилам выше |
| `partial` | есть частичный прогресс: `0 < value < target` |
| `missed` | ничего не отмечено |

### Мягкие серии

Главная механика против срывов: один пропуск не обнуляет прогресс.

```
softStreak(habit):
  streak = 0; misses = 0
  идём назад от сегодняшнего дня до createdAt:
    rest / future            → пропускаем, ничего не меняем
    done                     → streak += 1; misses = 0
    missed / partial, i == 0 → сегодня ещё открыт, пропускаем
    missed / partial         → misses += 1; если misses >= 2 → стоп
  вернуть streak
```

То есть две пропущенные даты подряд ломают серию, одна — поглощается. `bestStreak()` прогоняет тот же автомат
по всей истории вперёд и запоминает максимум — так «лучшая серия» никогда не уменьшается.

### Агрегаты

| Функция | Что считает |
| --- | --- |
| `dayProgress` | кольцо дня: только «действенные» привычки (`check`, `counter`, `duration`) |
| `weekProgress` | прогресс flex-привычки за календарную неделю с понедельника |
| `completionRate` | доля выполненных дней за окно 30/90 дней |
| `dayHeatStatus` | статус всего дня для общей карты: `done` только если закрыты все |

`negative` и `flex` выведены из кольца дня намеренно: «не делать» не требует ежедневного действия,
а гибкая привычка измеряется неделей. Иначе прогресс показывал бы выполнение там, где ничего не делалось.

<a id="storage"></a>

## 🗄 Хранение и импорт

- Ключ в `localStorage`: **`deeptracker.v1`**, запись — на каждое изменение состояния (`store.tsx`).
- `loadData()` при отсутствии данных создаёт стартовый набор привычек на языке браузера.
- `normalizeData()` — защитный слой: незнакомый `kind` превращается в `check`, нечисловые цели отбрасываются, даты проверяются регуляркой, мусорные дни удаляются. Поэтому старый или руками правленный JSON не ломает приложение.
- `parseImport()` бросает ошибку на чужой JSON (например, без непустого массива `habits`) — интерфейс показывает понятный тост.
- `toJson()` / `downloadJson()` — бэкап файлом `deeptracker-YYYY-MM-DD.json`.

<a id="pwa"></a>

## 📴 PWA и офлайн

- `public/manifest.webmanifest` — standalone, `start_url: ./`, иконки `any` + `maskable`.
- `public/sw.js` — две стратегии:
  - **навигация** — network-first с фолбэком на кэш: свежий деплой подхватывается сразу, офлайн открывается последняя версия;
  - **остальное** — stale-while-revalidate: мгновенный ответ из кэша и тихое обновление в фоне.
- Service worker регистрируется **только в продакшн-сборке** и только по `http(s)` — с `file://` он невозможен, а в dev он мешал бы HMR.
- **Правило:** поменял оболочку (иконки, манифест, статику) — подними `CACHE_VERSION` в `public/sw.js`, иначе у установивших приложение останется старая закэшированная версия. Хэшированные ассеты и `index.html` обновляются сами.
- `public/.nojekyll` — чтобы GitHub Pages не пытался обрабатывать файлы через Jekyll.

## 🎨 Палитра

Оба набора токенов лежат в `src/styles.css`: `:root` — тёмная тема (цвета сняты с дашборда DeepSeek Platform),
`[data-theme='light']` — строго чёрно-белая. Имена токенов одинаковые, поэтому все правила написаны один раз.

| Токен | Тёмная | Где используется |
| --- | --- | --- |
| `--bg` | `#141418` | фон страницы |
| `--surface` | `#1c1c1f` | поля ввода, чипы, нижняя навигация |
| `--surface-2` | `#333538` | карточки, модалка |
| `--surface-3` | `#3d4044` | выполненная карточка |
| `--line` / `--line-strong` | `#2b2c30` / `#43454a` | разделители / границы интерактивных элементов |
| `--fg` / `--muted` | `#f8f8fc` / `#a2a6b3` | основной / вторичный текст |
| `--pill` / `--pill-ink` | `#43454a` / `#ffffff` | активная вкладка |
| `--accent` | `#0070f3` | прогресс-бар, галочка, фокус |
| `--action-bg` / `--action-ink` | `#679efe` / `#0d1117` | основные кнопки |
| `--accent-soft` / `--accent-bright` | `#34415b` / `#cfe0ff` | баннер-подсказка |
| `--good` | `#22c55e` | закрытая неделя, успешный импорт |
| `--warn` | `#d5a51c` | частичный день, мягкое предупреждение |
| `--cell-done` / `--cell-partial` / `--cell-line` | `#679efe` / `#d5a51c` / `#5a5e66` | клетки heatmap |

Красного нет намеренно. Контраст проверен по WCAG: текст ≥ 4.5:1 на своих фонах, графические элементы ≥ 1.5:1.
Клетки heatmap держат отдельные токены, потому что лежат на серой карточке, а не на фоне страницы.

## 🧪 Тесты

```bash
npm test          # 25 тестов, ~0.4 c
npm run typecheck # tsc --noEmit отдельно
```

| Файл | Что проверяет |
| --- | --- |
| `src/lib/habits.test.ts` | правила тапа по всем пяти типам, статусы `rest`/`future`, мягкие серии (одна пропущенная дата поглощается, две ломают, сегодня не наказывается), `bestStreak`, клампы счётчика, накопление минут, кольцо дня, лимит трёх закреплённых, перестановка порядка, удаление привычки вместе с историей, экспорт/импорт, нормализация мусорного JSON |
| `src/app.test.tsx` | рендер оболочки и всех четырёх экранов через `react-dom/server` с подставленным `localStorage`: ловит падения на реальных данных, включая пустое состояние статистики и английскую локаль |

Тесты детерминированы: даты считаются от локального «сегодня», идентификаторы привычек фиксированы,
`localStorage` подменяется заглушкой.

<a id="scripts"></a>

## 🛠 Скрипты

| Команда | Что делает |
| --- | --- |
| `npm run dev` | dev-сервер на `127.0.0.1:5173` (явный IPv4 — см. [траблшутинг](deploy.md#troubleshooting)) |
| `npm run build` | `tsc --noEmit` + сборка в `dist/` |
| `npm run preview` | статический сервер продакшн-сборки на `127.0.0.1:4173` |
| `npm test` | прогон Vitest |
| `npm run typecheck` | только типы |
| `npm run icons` | перегенерировать `public/icons/*` и `public/og.png` |

`scripts/make-icons.mjs` не тянет графических библиотек: PNG собирается вручную (IHDR/IDAT/IEND + CRC32
и `zlib.deflateSync`), а галочка рисуется суперсэмплингом 4×4 с премультиплицированным усреднением —
поэтому скруглённые углы и концы штриха получаются гладкими.

`scripts/smoke.mjs` проверяет, что сервер или деплой реально отдаёт всю статику:

```bash
node scripts/smoke.mjs                            # dev на :5173
node scripts/smoke.mjs http://127.0.0.1:4173/     # локальный preview
node scripts/smoke.mjs https://<user>.github.io/<repo>/   # живой деплой
```

Скрипт сам определяет режим (dev или продакшн-сборка), качает `index.html`, точку входа или хэшированный бандл,
манифест, service worker, favicon и иконки, и падает с ненулевым кодом, если что-то не отдалось.

## 📦 Сборка

| Параметр | Значение |
| --- | --- |
| `base` | `'./'` — относительные пути, один и тот же `dist/` работает на project- и user-страницах Pages и на своём домене |
| `target` | `es2019` |
| JS | ~270 kB raw / **~83 kB gzip** |
| CSS | ~11 kB raw / **~3 kB gzip** |

Внешних CDN и шрифтов нет — страница не делает ни одного запроса наружу, поэтому и работает офлайн.

<a id="i18n"></a>

## 🌍 Локализация

Словари в `src/lib/i18n.ts`. `ru` — источник истины: тип `Dict` выводится из него, поэтому забытый или
опечатанный ключ в `en` ломает `npm run typecheck`, а не доезжает до продакшена. Подстановки — через `fill()`
(`{done} из {total}`). Стартовый набор привычек тоже локализован (`SEED_HABITS`).

Добавить язык: скопировать объект `en`, перевести, добавить в `STRINGS` и в тип `Lang`.
