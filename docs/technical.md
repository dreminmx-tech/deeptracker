# 🔧 Технические детали

Как устроен DeepTracker внутри: стек, данные, алгоритмы, PWA и тесты.
Для деплоя — [deploy.md](deploy.md).

<a id="stack"></a>

## 🧱 Стек

| Слой | Выбор | Почему так |
| --- | --- | --- |
| Сборка | **Vite 8** | мгновенный dev-сервер, статический `dist/` без рантайма |
| UI | **React 19** + TypeScript 7 (strict) | предсказуемое состояние, типы ловят опечатки в словарях |
| Состояние | React-контекст + `useState` | на таком объёме redux/zustand — лишняя зависимость |
| Хранение | `localStorage` | офлайн-first, ноль серверов, ноль аккаунтов |
| Офлайн | свой `public/sw.js` + манифест | без `vite-plugin-pwa`: меньше зависимостей, полный контроль |
| Тесты | Vitest (node-окружение) | логика в чистых модулях + `react-dom/server` для рендера |
| Иконки UI | **Lucide** (`lucide-react`) | ~3 КБ gzip; своих рисованных глифов в интерфейсе нет |
| Иконки приложения | свой PNG-энкодер на `zlib` | никаких `sharp`/`canvas` в зависимостях |

## 🗂 Структура

```
src/
  types.ts              типы данных: Habit, Entry, JournalNote, DayLog, AppData, Settings
  store.tsx             контекст стора, запись в localStorage на каждое изменение
  App.tsx               оболочка: пять вкладок (с deep-link по #hash), тема, язык, ролловер суток
  styles.css            обе темы: :root (тёмная) и [data-theme='light'] (чёрно-белая)
  lib/
    date.ts             локальные ключи дат YYYY-MM-DD, недели, Intl-форматирование
    habits.ts           чистая логика: статусы, мягкие серии, агрегаты, сводка по дням недели
    actions.ts          чистые мутации: тапы, счётчики, минуты, установка значения, CRUD привычек
    journal.ts          чистая логика журнала: лента дней, черновик, отправка заметки, правка
    storage.ts          localStorage, нормализация, экспорт/импорт, скачивание файла
    i18n.ts             словари ru/en + стартовый набор привычек
    useInstallPrompt.ts хук установки PWA
    useKeyboardInset.ts высота клавиатуры на iOS: --kb и data-typing для панели журнала
    version.ts          версия приложения для настроек
  components/
    TodayView.tsx       экран «Сегодня»: список галочек, подсказка про вчера, быстрые дела
    JournalView.tsx     журнал-лента: композер внизу, правка и удаление прямо в нём
    HabitsView.tsx      управление: блоки «Делать» и «Не делать», порядок, закрепление, архив (шторка)
    StatsView.tsx       серия, лучшая серия, неделя точками, серии по привычкам
    SettingsView.tsx    язык, тема, экспорт/импорт, установка
    HabitRow.tsx        единственный паттерн строки: галочка, название, открытие настроек, одно действие
    habitText.ts        расписание привычки как текст («пн, ср, пт», «по будням»)
    ActionSheet.tsx     шторка управления: иконка + текст
    HabitForm.tsx       создание и редактирование: название, тип, дни, «в главном»
    Checkbox.tsx        квадратная галочка — главный тап-таргет
    Modal.tsx           шторка-колонка: заголовок и футер всегда видны, прокрутка в теле
    Toast.tsx           короткое сообщение на два редких случая (импорт, лимит «главных»)
scripts/
  make-icons.mjs        PNG-иконки и og.png (свой энкодер + растеризатор)
  shots.mjs             скриншоты через Chrome DevTools Protocol (docs/screenshots)
  smoke.mjs             проверка, что сервер и деплой отдают всю статику
```

Правило: всё в `src/lib/*` — чистые функции без React и DOM. Их тестируют напрямую, компоненты остаются тонкими.

## 🎛 Интерфейс: правила

Система, а не набор удачных решений. Всё в `src/styles.css`:

| Что | Правило |
| --- | --- |
| Отступы | только `--s1…--s6` (4/8/12/16/24/32). Экран — `gap: var(--s5)` (`.stack`), карточка — `padding: var(--s4)` и `gap: var(--s3)`, подписанный блок внутри карточки — `--s2` (`.block`). Своих `margin` у блоков нет: ритм задаёт родитель |
| Высоты | **только контрольная шкала**: `--control-sm` (32 — сегменты и тихие пилюли), `--control`/`--tap` (44 — любая подписанная кнопка, любое поле ввода и кнопка отправки), `--icon` (40 — любая квадратная кнопка-иконка), `--row` (56 — строка списка). Плюс две полосы внизу экрана: `--tabs` (72 — нижняя навигация) и `--jbar` (панель заметки в журнале: её высота переменная, поэтому её измеряет сам журнал). Раньше в файле жили 32/34/36/38/40/48/52/54 — отсюда и бралась «разномастность» |
| Типографика | только `--t-xs…--t-3xl` (12/13/15/17/22/32/48) и два веса: `--w-normal` (500) и `--w-strong` (650). Единственное исключение — подписи вкладок на экранах уже 360px: пять вкладок не влезают там в 12px, и 11px лучше переноса «Статисти/ка» |
| Форма | `--radius` (12) у карточек и тоста, `--radius-sm` (8) у **каждого** элемента управления: кнопки, сегменты, дни недели, поля ввода, и `--radius-lg` (20) у композера журнала с его круглыми кнопками — это единственное место, где форма скруглена сильнее: там она читается как «поле чата», а не как кнопка. Полностью круглыми остались полосы (метр дня, отметка дня в статистике) и кнопки композера |
| Карточка | один паттерн: заголовок, подпись, содержимое; 16px внутри, 12px между детьми, без «пустых» наполовину блоков |
| Строка | **один** компонент `HabitRow` на все списки: галочка, название, одно действие. Никакой колонки значений в строке нет: привычка сделана или нет, и строка никогда не спрашивает «сколько?». Название тянется, действие прижато к правому краю (`--icon` = 40px) — поэтому у всех строк списка правый край совпадает |
| Настройки | строки, а не плашки: `Язык [Русский|English]` — подпись слева, маленький переключатель справа. Полноширинный сегмент на бинарный выбор был самым тяжёлым элементом в приложении |
| Иерархия | что вообще имеет право быть громким — см. таблицу ниже |
| Опасное | отдельный токен `--danger` и только для разрушительных действий (удалить данные, удалить привычку, удалить заметку в журнале). Ни одно состояние привычки красным не красится |

Что имеет право быть громким:

| Роль | Чем показывается |
| --- | --- |
| Состояние привычки | **единственный синий** `--accent`: отмеченная галочка и главная кнопка шторки. На большинстве экранов синего нет вовсе |
| «Ты здесь» | нейтральная приподнятая пилюля `--pick` (`#3a3d47`): активная вкладка, выбранный язык и тема, выбранные дни недели в форме. Это навигация и настройки, а не состояние, поэтому синего тут нет |
| Сегодня | на статистике сегодняшний день отмечен синим **кольцом**, а не заливкой: заливка точки значит «был прогресс», и пустой сегодня не должен выглядеть закрытым. В журнале сегодняшняя дата — единственное светлое слово в ленте (`--fg` против `--muted` у прошлых дней): точка отсчёта без слова «сегодня» |
| Границы | карточка читается тонкой светлой линией `--line` (`#33353c`), а не тяжёлой заливкой: `--surface-2` — всего один шаг над фоном. Сильная граница `--line-strong` — только у интерактивных элементов (кнопки, поля, пилюли) |
| Текст | два уровня: `--fg` для названий и значений, `--muted` для подписей. Длинных объяснений в интерфейсе нет: каждая фраза — это то, что человек читает вместо того, чтобы закрыть привычку |

Экран «Сегодня» — список галочек и ничего больше:

- Тап по строке = сделано, ещё тап = снято. У «не делать» галочки нет: срыв отмечается явной
  кнопкой `Ban`, чтобы случайное касание не портило серию. Больше в строке нет ничего: раньше здесь
  жили `− значение +`, «просто начни» и значение дня, и именно из-за них приложение казалось сложным.
- **У текста нет полупрозрачных состояний.** Нажатие и наведение раньше гасили название привычки
  (`opacity`), и на телефоне буквы успевали перерисоваться четыре-пять раз за нажатие — это читалось
  как «текст мерцает». Теперь отклик на палец даёт квадрат галочки (`scale(0.9)`), наведение — только
  цвет, а состояние «сделано» меняет цвет названия **одним кадром** (`transition: none`).
- **В списке привычек тап по названию открывает настройки привычки** — те же, что стрелка справа
  (`onOpenMain`): целиться в один угол строки неудобно, а случайного действия у тела строки нет.
  Закреплённая привычка — по-прежнему единственная, у кого название жирнее.
- **Привычка больше не спрашивает «сколько».** Ни счётчиков, ни целей, ни минут, ни чипов быстрого
  ввода: если дело требует двадцати минут, это задача, а не привычка. Часы в строке запрета — не
  счётчик сделанного, а таймер тяги, и он считает время вниз, ничего не записывая. В модели данных
  старые типы остались (`counter`, `duration`, `flex`), чтобы не потерять историю и бэкапы, но
  интерфейс их не создаёт: новая привычка — всегда галочка. Один тап закрывает и старую привычку
  с целью: `tapHabit` пишет сразу всю цель, поэтому «6 стаканов» отмечаются так же, как «выпить таблетки».
- Прошлое — **всегда в одном тапе**: слева дата словами, справа две стрелки «день назад /
  день вперёд» (`›` выключена на сегодня). Раньше здесь была полоса недели, потом её сменила ссылка
  «Открыть вчера», которая появлялась только если вчера было *полностью* пусто — и правка вчера
  стала невозможной. Стрелки исправляют именно это: дата всегда написана, поэтому «какой это день»
  не загадка, а вчера доступно в любом случае. Из прошлого один тап назад в сегодня — ссылка
  «Сегодня». Привычки, которых в тот день ещё не было, не показываются (`habitsUpTo`).
- **Одна короткая фраза о дне** вместо уведомлений: «На сегодня всё.» когда день закрыт и
  «Вчера было пусто. Один пропуск прощается.» когда есть риск.
- **«Быстрые дела»** — короткий инбокс на день для нерутинных дел и идей (галочка, текст, удаление).
  Раньше блок назывался «Мысли на сегодня» и притворялся дневником; теперь мысли живут в журнале,
  а здесь остались задачи на один день. Кнопка добавления живёт **внутри поля**, в правом нижнем углу,
  как отправка в композере журнала: строка читается одним целым, а не полем и отдельной кнопкой рядом.
  Пустое поле кнопку не показывает вовсе (`data-ready` → `visibility: hidden`), потому что отправлять
  нечего. Пока в поле курсор, нижнее меню уезжает — то же `data-typing` и `--kb`, что и в журнале,
  иначе меню перекрывало бы то, что человек печатает; поднявшуюся клавиатуру поле догоняет
  `scrollIntoView` (`scroll-margin-bottom` у `.app` держит запас снизу).
- Никаких всплывающих «Отменить»: раньше тост предлагал откат для срыва, удалённой мысли и привычки
  со старой целью. Отмена требовала читать плашку и успевать на неё нажать — то есть внимания в тот
  момент, когда его нет. Вместо неё действует простое правило: **то, что нельзя задеть случайно,
  не боится промаха** (срыв — единственная кнопка `Ban`, заметка журнала не удаляется вовсе), а
  обратимое действие снимается повторным тапом.
- Управление (изменить, порядок, закрепить, архив) живёт в шторке вкладки «Привычки»: там действия редкие,
  и им уместно иметь подписи — иконка + текст. Список разведён на два блока с подписями: **«Делать»**
  и **«Не делать»** — это два разных вопроса к себе, и привычка-запрет не должна стоять в одном ряду
  с привычкой-действием. Архив остаётся третьим блоком.
- **Таймер «держусь» — механика для «не делать» и только для них.** Срыв отмечает срыв, но не помогает
  его пережить: тяга живёт минутами, и в эти минуты человеку нужно время, а не ещё один квадрат. В строке
  запрета вместо стрелки стоят часы (`UrgeButton`) — они открывают панель под строкой: подпись
  «Сдержаться · 15 мин», крупные цифры (`--t-3xl`, `tabular-nums`, чтобы секунды не дёргали вёрстку),
  кнопка «Сдержался» во всю ширину и тихие строки «Всё равно сорвался» и «Закрыть» под ней. Панель
  считает остаток **от часа окончания**, а не накоплением тиков: свёрнутая вкладка может проспать
  полминуты, и накопленный счёт соврал бы. Таймер один на экран (одна тяга за раз) и живёт в состоянии
  представления — в данные он не пишет ничего, пока не нажата кнопка. «Сдержался» закрывает панель и
  говорит плашкой, «сорвался» пишет срыв (`tapHabit`), а если срыв уже стоит, панель предлагает вернуть
  «чисто» — больше снять его нечем. Длительность (5/10/15/30 мин) выбирается в форме привычки и лежит
  в `resist`; значение по умолчанию — пять минут, потому что перетерпеть пять минут может каждый.
  Панель стоит **рядом со строкой, а не внутри неё**: внутри она попала бы в колонку действия шириной
  сорок пикселей и уехала бы за край списка.
- Числа везде с `font-variant-numeric: tabular-nums`, чтобы счётчики не дёргали вёрстку.
- Вкладки адресуются хэшем (`/#journal`, `/#stats`), поэтому состояние открывается по ссылке и снимается скриптом.

Журнал — **лента, как чат, но без собеседника**. Один экран, одно поле внизу, ноль настроек: папок,
тегов и поиска нет, потому что всё это — трение перед тем, как записать строчку.

- Лента идёт по дням **снизу вверх**: сверху позавчера, ниже вчера, в самом низу сегодня. Внутри дня
  заметки тоже старые сверху, новые снизу: новая мысль всегда встаёт туда, где на неё смотришь.
- **Ни одной разделительной линии.** Дни и заметки разделяет только воздух (`--s6` между днями, `--s3`
  между заметками), а страницу держат даты. Линия над панелью тоже убрана: композер читается своей
  рамкой, а не чертой во всю ширину. **До меню — 12px**, и это буквально размер: под коробкой остаётся
  её padding `--s2`, а ниже — отдельный слой `.jbar-gap` в `--s1`, в сумме 8 + 4 = 12px. Больше не надо:
  фон панели и меню — одна краска, и зазор в 20px читался как дыра, а не как воздух. Зазор вынесен
  в отдельный слой, а не в padding панели, потому что `env(safe-area-inset-bottom)` складывался бы
  с таким же отступом в меню и на телефоне с вырезом воздух превращался бы в 32px.
- В дне нет ничего, кроме даты и текста: ни прогресса по привычкам, ни счётчиков. Заголовок дня — дата
  словами (`formatDay`), у сегодняшней даты цвет `--fg`, у прошлых — `--muted`. Светлых слов в ленте
  ровно два: сегодня и день, в который пишет поле.
- **Композер** (`.jbar` + `.jcomposer-box`) — одна скруглённая коробка (`--radius-lg`, 20px) во всю
  ширину панели; края держат `env(safe-area-inset-left/right)`, так что на телефоне с вырезом поле
  не липнет к самому краю. Внутри коробки справа внизу — круглая кнопка. Рамку и фон несёт коробка,
  поле внутри прозрачное и без границ.
- **Enter — обычный Enter**, перенос строки: в заметке бывает несколько строк, и отбирать у него перенос
  было ошибкой первой версии. Отправляет круглая кнопка со стрелкой (`.jsend`), и она единственная синяя
  вещь на экране — но только когда есть что отправлять; пустая заметка ничего не делает и не зовёт.
- **Каждое нажатие клавиши сохраняется сразу** (`setDraft` → `drafts[день]` в `AppData`). Черновик —
  это запись в `drafts` с непустым текстом; пустой текст ключ удаляет, потому что «поле открыто» —
  это состояние композера, а не данные. Поэтому закрытое приложение, свёрнутый браузер и перезагрузка
  не теряют недописанную фразу: `unfinishedDay()` при открытии вкладки нацеливает поле в тот день,
  где остался черновик.
- **Открытие вкладки ставит ленту вниз** (`scrollTo` по `scrollHeight`), к последней заметке и полю:
  в журнал приходят писать, а не листать. Новая заметка тоже прокручивает ленту вниз, а высота панели
  (поле растёт под текст) измеряется `ResizeObserver` и уходит в `--jbar`, которым задан запас снизу.
- **Клавиатура поднимает нижние полосы, а не закрывает их.** В `index.html` у viewport добавлен
  `interactive-widget=resizes-content`: Android укорачивает само окно, и панель с меню оказываются над
  клавиатурой без единой строки JS. iOS Safari окно не укорачивает, поэтому `useKeyboardInset(active)`
  считает по `visualViewport`, сколько пикселей клавиатура закрывает, и пишет это в `--kb`. На `--kb`
  поднимаются **обе** полосы — `.jbar` и `.tabs`, — а запас снизу в `.app` растёт на ту же высоту,
  иначе последняя заметка осталась бы за панелью. Меню не прячется: раньше оно уезжало на
  `translateY(100%)`, и это оказалось ловушкой — на Android его не возвращало ничто, кроме ухода
  со вкладки. Теперь меню всегда на экране, поверх него ничего не «висит», и единственное, что
  действительно уезжает, — сама клавиатура.
- **Кнопка «назад» на Android** (`useBackButton`) убирает верхний слой, а не закрывает приложение:
  открыта шторка — закрывается она, идёт набор — снимается фокус и клавиатура уезжает. Только
  следующее нажатие, когда поверх экрана уже ничего нет, уходит в браузер. Работает через историю:
  на время слоя в неё кладётся свой шаг (`pushState`), а `popstate` означает «просили убрать слой».
  Слоёв в приложении два — оболочка (клавиатура) и шторка, — и они живут в одном списке: отвечает
  только верхний, поэтому одно нажатие убирает одно, а не всё сразу. Пока открыта шторка, клавиатура
  в очередь не встаёт: иначе «назад» снимал бы фокус с поля внутри шторки, а сама шторка оставалась.
  Кнопка «назад» в браузере и Escape работают одинаково: и то и другое закрывает шторку.
- **Правка и удаление — там же, в поле.** Тап по заметке поднимает её текст в композер (`data-mode="edit"`),
  над коробкой появляется строка «Правишь запись 14:32», а вместо стрелки — две круглые кнопки: корзина
  (`--danger`, единственное красное) и галочка. Набор текста сохраняется посимвольно (`editNote`), так что
  из режима правки нельзя выйти с потерями: галочка просто заканчивает, корзина удаляет (`removeNote` —
  и день уходит из ленты, если это была последняя заметка). Пустой текст в правке при нажатии галочки
  тоже удаляет заметку: пустой заметки не существует.
- Любой прошлый день нацеливается кнопкой `+` в своей строке, и заметка уходит **именно в тот день**:
  над полем видно дату и ссылку «Сегодня», а сам день в ленте помечен `data-target`. Та же кнопка
  превращается в галочку и возвращает поле к сегодняшнему дню.
- Длина одной заметки — `NOTE_MAX` (2000 знаков). Поле растёт под текст и перестаёт расти на `FIELD_MAX`
  (132px); когда текст длиннее, поле прокручивается **к каретке** (`scrollTop = scrollHeight`), иначе
  на экране оставались бы первые строки, а писал бы человек вслепую.
- Дни без заметок в ленту не попадают: пустого «понедельника» в журнале не существует. Сегодняшний
  день есть всегда, а день-цель дорисовывается, даже если он пуст, — иначе кнопке `+` некуда было бы
  деться.

Статистика — **две цифры и семь точек**, и это всё. Раньше здесь были окна 30/90, переключатель
диапазона, легенда из четырёх образцов, полоса на тридцать дней и по тридцать столбиков на каждую
привычку: вкладка превращалась в дашборд, на который не хочется заходить, а «длинные непонятные
графики» не отвечали ни на один вопрос.

- Заголовок — такая же карточка, как остальные: серия («23 дня подряд») и лучшая серия за 90 дней.
  Лучшая считается на квартале, а не на неделе: за семь дней она всегда упирается в семь.
- **Эта неделя** — семь точек (`dayHeatStatus`), точка это день: была работа или нет. Сегодня
  отмечено синим кольцом, а не заливкой. Ниже одна строка: «Дней с делами: 5 из 7».
- **По привычкам** — строки одного списка: имя и серия, и список разведён на **«Делать»** и
  **«Не делать»** теми же подписями, что на «Сегодня» и в «Привычках»: у запрета серия означает
  чистые дни, и стоять в одном ряду с обычными привычками он не должен. Всё. Проценты за окно,
  лучшие и худшие привычки, тон недели и вывод по дням недели убраны: это был текст, который читают
  вместо того, чтобы закрыть привычку.

Иконки — **Lucide** (`lucide-react`), ~3 КБ gzip в бандле. Свои рисованные SVG убраны:
самодельные `Play`, `±`, таймер и текстовый `✕` выглядели кустарно.

Настройки — четыре карточки вместо шести, и на всей вкладке **нет ни одного синего** (у настроек нет
главного действия, значит и акцента нет):

- «Интерфейс» — две строки: подпись слева, маленький переключатель справа. Раньше это были две
  полноширинные плашки по 44px на бинарный выбор — самый тяжёлый элемент в приложении. У обоих
  переключателей **одна ширина** (176px, половины равные): «Тёмная/Светлая» ровно такой же ширины, как
  «Русский/English», иначе две строки одного смысла выглядят разными. Высота контрола — ровно
  `--control` (44px), как у кнопок данных: высота задана **контейнеру**, а внутренняя половина ниже
  на padding и рамку (36 + 3 + 3 + 1 + 1 = 44), иначе сам контрол выходил бы на 8px выше соседей.
  Тема названа по тому, что человек видит, — тёмная и светлая, а не чёрная и белая.
- Тот же счёт и у выбора в форме привычки («Делать / Не делать» и ряд длительностей таймера):
  контрол ровно `--control`, внутренние половины — 36px. Раньше он был на 8px выше соседних
  кнопок и читался как другой по весу элемент.
- «Данные» — две **одинаковые** кнопки (скачать / загрузить) во всю ширину карточки, строка состояния
  бэкапа и «опасная зона» ниже. Ручная вставка JSON убрана: бэкап скачивают и загружают файлом, а поле
  для вставки текста было третьим способом сделать то же самое.
- Все кнопки в карточках — одной ширины (во всю карточку). Узкая кнопка «Удалить все данные» рядом с
  широкими соседями читалась как случайно прилипшая.
- «Опасная зона» помечена **одним** красным — кнопкой. Красный заголовок над ней убран: три красных
  элемента подряд превращали редкое действие в тревогу.

Шторка (модалка, форма, быстрое окно) — колонка: заголовок и футер видны всегда, прокручивается только
тело (`overflow: hidden` у `.sheet`, `overflow-y: auto` у `.sheet-body`). Раньше футер уезжал под сгиб
на коротких экранах, и «Сохранить» в форме привычки приходилось искать прокруткой: форма открывалась,
а сохранить её было нельзя. Плюс у новой привычки курсор сразу стоит в поле названия.

Шрифт — **Manrope Variable** (`@fontsource-variable/manrope`), самохостинг с сабсетами cyrillic + latin:
39 КБ на первую загрузку, дальше из кэша service worker. Внешних запросов по-прежнему ноль.

<a id="data"></a>

## 💾 Модель данных

```ts
interface Habit {
  id: string;
  name: string;
  kind: 'check' | 'counter' | 'duration' | 'negative' | 'flex';
  target?: number;   // counter: цель в день, duration: целевые минуты
  unit?: string;     // «стаканов», «мин»
  perWeek?: number;  // flex: сколько раз в неделю
  step?: number;     // counter: шаг кнопок +/−
  days?: number[];   // дни недели, 0 = понедельник; нет поля — каждый день
  tiny?: string;     // версия привычки на 2 минуты для «просто начни»
  resist?: number;   // negative: длина таймера «держусь» в минутах (5/10/15/30)
  pinned?: boolean;  // показывать в «Главном сегодня» (максимум 3)
  archived?: boolean;
  createdAt: string; // ISO; дни раньше этой даты не считаются пропусками
  order: number;     // плотный порядок 0..n-1
}

interface Entry {
  value?: number;    // counter/duration — накопленное, negative — число срывов
  done?: boolean;    // check/flex — выполнено
  note?: string;
}

interface DayLog {
  entries: Record<string, Entry>; // ключ — id привычки
  dump: DumpItem[];               // «быстрые дела» на этот день
}

interface JournalNote {
  id: string;
  text: string;      // многострочный: переносы строк сохраняются
  createdAt: string; // ISO; в ленте показываются только часы и минуты
}

interface AppData {
  version: number;
  habits: Habit[];
  days: Record<string, DayLog>;             // ключ — локальная дата YYYY-MM-DD
  journal: Record<string, JournalNote[]>;   // заметки дня, новые сверху
  drafts: Record<string, string>;           // ключ — открытое поле, значение — текст в нём
  settings: { lang: 'ru' | 'en'; theme: 'dark' | 'light' };
}
```

Принципы:

- **Дни адресуются локальной датой** (`YYYY-MM-DD` в таймзоне пользователя), а не UTC: «сегодня» должно совпадать с календарём на стене.
- **Пустое не хранится.** Снятие галочки удаляет запись, а день без записей и без быстрых дел удаляется целиком — база не пухнет от пустых объектов. В журнале пустая заметка не создаётся вовсе, а день без заметок в `journal` просто отсутствует; исключение — ключ в `drafts`: он означает «поле открыто», и его значение может быть пустой строкой.
- **Хронология важна.** `createdAt` отделяет «привычки ещё не было» от «привычка пропущена»: до даты создания день имеет статус `rest` и не портит статистику.

<a id="logic"></a>

## 🧠 Логика привычек

### Правила выполнения

| Тип | Выполнено когда | Значение по умолчанию |
| --- | --- | --- |
| `check` | есть запись с `done: true` | не выполнено |
| `negative` | `value === 0` — то есть срывов нет | **выполнено** (чисто по умолчанию) |
| `counter` | `value >= target` | не выполнено |
| `duration` | `value >= target` (минуты) | не выполнено |
| `flex` | есть запись с `done: true` | `rest` — день ничего не требует |

Первые два типа — то, что создаёт интерфейс. Остальные три остались в модели и в правилах выше,
чтобы **читать** старые данные и бэкапы: привычка с целью ведёт себя как галочка (один тап пишет
всю цель), а её `target`, `unit`, `perWeek` и `tiny` больше нигде не показываются. Отредактированная
через форму привычка становится `check` или `negative` — цель при этом исчезает, и это осознанный
выбор: приложение, которое спрашивает «сколько стаканов», и есть та сложность, от которой оно лечит.

### Статус дня

`dayStatus(data, habit, key)` возвращает одно из пяти значений:

| Статус | Когда |
| --- | --- |
| `future` | дата позже сегодня |
| `rest` | день раньше `createdAt`, день вне расписания, либо flex-привычка без записи |
| `done` | по правилам выше |
| `partial` | есть частичный прогресс: `0 < value < target` |
| `missed` | ничего не отмечено |

### Расписание

У привычки может быть список дней недели — `Habit.days`, `0` = понедельник. День вне списка становится
`rest`, а не пропуском: он не рвёт серию, не попадает в кольцо дня и в процент выполнения, а в
полосе-графике рисуется как «не требовалось». На экране «Сегодня» такая привычка не показывается —
вместо неё одна ссылка «Показать не по расписанию (1)», чтобы её всё-таки можно было отметить.

«Каждый день» хранится как **отсутствие поля**: пустой список и все семь дней нормализуются в `undefined`,
чтобы у самого частого случая не было состояния, которое можно рассогласовать. Гибкие привычки
(`flex`) живут по недельной цели и расписание игнорируют.

### Мягкие серии

Главная механика против срывов: один пропуск не обнуляет прогресс.

```
softStreak(habit):
  streak = 0; misses = 0
  идём назад от сегодняшнего дня до createdAt:
    rest / future            → пропускаем, ничего не меняем
    done                     → streak += 1; misses = 0
    missed / partial, i == 0 → сегодня ещё открыт, пропускаем
    missed / partial         → misses += 1; если misses >= 2 → стоп
  вернуть streak
```

То есть две пропущенные даты подряд ломают серию, одна — поглощается. `bestStreak()` прогоняет тот же автомат
по всей истории вперёд и запоминает максимум — так «лучшая серия» никогда не уменьшается.

### Агрегаты

| Функция | Что считает |
| --- | --- |
| `dayProgress` | кольцо дня: только «действенные» привычки (`check`, `counter`, `duration`) |
| `scheduledOn` | нужна ли привычка в этот день недели |
| `habitsUpTo` | привычки, которые уже существовали на эту дату: прошлое не требует того, чего ещё не было |
| `weekProgress` | прогресс flex-привычки за календарную неделю с понедельника |
| `completionRate` | доля выполненных дней за переданное окно (библиотечная функция: интерфейс её больше не зовёт) |
| `habitCounts` | сколько раз привычка закрыта и сколько раз её ждали (для гибких — недельная цель) |
| `weekReview` | итоги недели: живых дней, лидер и отстающий (библиотека; интерфейс показывает только счёт дней) |
| `weekdayRates` | доля закрытых привычек по дням недели: где именно проваливается (библиотека, из интерфейса убрано) |
| `missedYesterday` | сколько привычек пропущено вчера и всё ещё открыто сегодня |
| `dayHeatStatus` | статус всего дня для общей карты: `done` только если закрыты все |

`negative` и `flex` выведены из кольца дня намеренно: «не делать» не требует ежедневного действия,
а гибкая привычка измеряется неделей. Иначе прогресс показывал бы выполнение там, где ничего не делалось.

<a id="storage"></a>

## 🗄 Хранение и импорт

- Ключ в `localStorage`: **`deeptracker.v1`**, запись — на каждое изменение состояния (`store.tsx`).
- `loadData()` при отсутствии данных создаёт стартовый набор привычек на языке браузера.
- `normalizeData()` — защитный слой: незнакомый `kind` превращается в `check`, нечисловые цели отбрасываются, даты проверяются регуляркой, мусорные дни удаляются, заметки журнала без текста и ключи `journal`/`drafts` не по формату даты отбрасываются — а всё остальное в ленте остаётся. Поэтому старый или руками правленный JSON не ломает приложение.
- `parseImport()` бросает ошибку на чужой JSON (например, без непустого массива `habits`) — интерфейс показывает понятный тост.
- `toJson()` / `downloadJson()` — бэкап файлом `deeptracker-YYYY-MM-DD.json`.
- **Дата последнего бэкапа** (`settings.lastExport`) пишется при экспорте и переживает экспорт/импорт. Данные живут только в этом браузере, поэтому экран настроек сам говорит, когда файл скачивали в последний раз, и напоминает, если прошло три недели или бэкапа не было вовсе. Это единственное напоминание в приложении, и оно появляется только когда есть что терять.

<a id="pwa"></a>

## 📴 PWA и офлайн

- `public/manifest.webmanifest` — standalone, `start_url: ./`, иконки `any` + `maskable`.
- `public/sw.js` — две стратегии:
  - **навигация** — network-first с фолбэком на кэш: свежий деплой подхватывается сразу, офлайн открывается последняя версия;
  - **остальное** — stale-while-revalidate: мгновенный ответ из кэша и тихое обновление в фоне.
- Service worker регистрируется **только в продакшн-сборке** и только по `http(s)` — с `file://` он невозможен, а в dev он мешал бы HMR.
- **Правило:** поменял оболочку (иконки, манифест, статику) — подними `CACHE_VERSION` в `public/sw.js`, иначе у установивших приложение останется старая закэшированная версия. Хэшированные ассеты и `index.html` обновляются сами.
- `public/.nojekyll` — чтобы GitHub Pages не пытался обрабатывать файлы через Jekyll.

<a id="palette"></a>

## 🎨 Палитра

Оба набора токенов лежат в `src/styles.css`: `:root` — тёмная тема (цвета сняты с дашборда DeepSeek Platform),
`[data-theme='light']` — строго чёрно-белая. Имена токенов одинаковые, поэтому все правила написаны один раз.

| Токен | Тёмная | Где используется |
| --- | --- | --- |
| `--bg` | `#131317` | фон страницы |
| `--surface` | `#1b1c20` | поля ввода (включая поле журнала), нижняя навигация — врезанные «колодцы» |
| `--surface-2` | `#23242a` | карточки и сгруппированные списки — один тихий шаг над фоном |
| `--surface-3` | `#2e303a` | наведение, активная кнопка-иконка |
| `--line` / `--line-strong` | `#33353c` / `#4a4d56` | тонкая граница карточки и разделитель строк / сильная граница интерактивных элементов |
| `--fg` / `--muted` | `#f7f8fc` / `#a4a8b4` | названия и все значения / подписи |
| `--pick` / `--pick-ink` | `#3a3d47` / `#f7f8fc` | «ты здесь»: активная вкладка, язык и тема, дни недели в форме |
| `--accent` / `--accent-ink` | `#0070f3` / `#ffffff` | **единственный синий**: отмеченная галочка, главная кнопка шторки, отправка и «готово» в журнале (отправка — только когда есть что отправлять), фокус, сегодняшний день в статистике |
| `--good` | `#22c55e` | успешный импорт |
| `--cell-done` | `#b4b9c5` | нейтральная заливка дня: метр прогресса на экране «Сегодня» |
| `--danger` / `--danger-line` / `--danger-soft` | `#f2555a` / `#7c3437` / `rgba(242,85,90,.14)` | только разрушительные действия |

Жёлтого нет: красный — единственный дополнительный оттенок, и он закреплён за опасными действиями
(«Удалить все данные»), а не за состояниями привычек: пустая клетка не оценка. Синего ровно два
места — отмеченная галочка и главная кнопка шторки; на статистике синим кольцом отмечен только
сегодняшний день. Контраст проверен по WCAG: текст ≥ 4.5:1 на своих фонах. У текста нет
полупрозрачных состояний: `opacity` у названия привычки не меняется ни при нажатии, ни при наведении —
прозрачный текст перерисовывается на каждом кадре и на телефоне мигает. Состояние «сделано» —
мгновенная смена цвета на `--muted` (одним кадром, без перехода).

## 🛠 Скрипты

| Команда | Что делает |
| --- | --- |
| `npm run dev` | dev-сервер на `127.0.0.1:5173` (явный IPv4 — см. [траблшутинг](deploy.md#troubleshooting)) |
| `npm run build` | `tsc --noEmit` + сборка в `dist/` |
| `npm run preview` | статический сервер продакшн-сборки на `127.0.0.1:4173` |
| `npm test` | прогон Vitest |
| `npm run typecheck` | только типы |
| `npm run icons` | перегенерировать `public/icons/*` и `public/og.png` |
| `npm run shots` | снять скриншоты всех экранов в `docs/screenshots` (нужен запущенный `npm run preview`) |

`scripts/make-icons.mjs` не тянет графических библиотек: PNG собирается вручную (IHDR/IDAT/IEND + CRC32
и `zlib.deflateSync`), а галочка рисуется суперсэмплингом 4×4 с премультиплицированным усреднением —
поэтому скруглённые углы и концы штриха получаются гладкими.

`scripts/shots.mjs` управляет headless Chrome по DevTools Protocol: подставляет демо-данные за 24 дня
(вместе с заметками журнала) init-скриптом (до гидратации приложения — иначе гонка), открывает вкладки
по хэшу, при необходимости нажимает одну кнопку (`click` / `clickJs` — например, «+» у прошлого дня)
и сохраняет PNG. Путь к браузеру — `CHROME_PATH`, адрес — `SHOTS_BASE`.

`scripts/smoke.mjs` проверяет, что сервер или деплой реально отдаёт всю статику и SEO-разметку:

```bash
node scripts/smoke.mjs                            # dev на :5173
node scripts/smoke.mjs http://127.0.0.1:4173/     # локальный preview
node scripts/smoke.mjs https://<user>.github.io/<repo>/   # живой деплой
```

Скрипт сам определяет режим (dev или продакшн-сборка), качает `index.html`, точку входа или хэшированный
бандл, манифест, service worker, favicon, иконки, `robots.txt`, `sitemap.xml`, `og.png`, проверяет
`<title>`, `description`, `canonical`, Open Graph, Twitter-card и JSON-LD, и падает с ненулевым кодом,
если чего-то не хватает.

<a id="build"></a>

## 📦 Сборка

| Параметр | Значение |
| --- | --- |
| `base` | `'./'` — относительные пути, один и тот же `dist/` работает на project- и user-страницах Pages и на своём домене |
| `target` | `es2019` |
| JS | ~283 kB raw / **87.3 kB gzip** (включая ~3 КБ иконок Lucide) |
| CSS | ~23.5 kB raw / **7.7 kB gzip** |
| Шрифт | `assets/manrope-*-wght-normal.woff2`, 5 сабсетов ~72 КБ в сборке; браузер скачивает только cyrillic + latin (~39 КБ) |
| Артефакты | `index.html`, `assets/*`, плюс всё из `public/`: манифест, `sw.js`, `robots.txt`, `sitemap.xml`, `og.png`, иконки |

Внешних CDN и запросов наружу нет — шрифт самохостится из бандла, поэтому приложение работает офлайн.

## 🌍 Локализация

Словари в `src/lib/i18n.ts`. `ru` — источник истины: тип `Dict` выводится из него, поэтому забытый или
опечатанный ключ в `en` ломает `npm run typecheck`, а не доезжает до продакшена. Подстановки — через `fill()`
(`{done} из {total}`). Стартовый набор привычек тоже локализован (`SEED_HABITS`).

Добавить язык: скопировать объект `en`, перевести, добавить в `STRINGS` и в тип `Lang`.
