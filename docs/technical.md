# 🔧 Технические детали

Как устроен deeptracker внутри: стек, данные, алгоритмы, PWA и тесты.
Для деплоя — [deploy.md](deploy.md).

<a id="stack"></a>

## 🧱 Стек

| Слой | Выбор | Почему так |
| --- | --- | --- |
| Сборка | **Vite 8** | мгновенный dev-сервер, статический `dist/` без рантайма |
| UI | **React 19** + TypeScript 7 (strict) | предсказуемое состояние, типы ловят опечатки в словарях |
| Состояние | React-контекст + `useState` | на таком объёме redux/zustand — лишняя зависимость |
| Хранение | `localStorage` | офлайн-first, ноль серверов, ноль аккаунтов |
| Офлайн | свой `public/sw.js` + манифест | без `vite-plugin-pwa`: меньше зависимостей, полный контроль |
| Тесты | Vitest (node-окружение) | логика в чистых модулях + `react-dom/server` для рендера |
| Иконки UI | **Lucide** (`lucide-react`) | 16 иконок, ~3 КБ gzip; своих рисованных глифов в интерфейсе нет |
| Иконки приложения | свой PNG-энкодер на `zlib` | никаких `sharp`/`canvas` в зависимостях |

Правило: всё в `src/lib/*` — чистые функции без React и DOM. Их тестируют напрямую, компоненты остаются тонкими.

## 🎛 Интерфейс: правила

Система, а не набор удачных решений. Всё в `src/styles.css`:

| Что | Правило |
| --- | --- |
| Отступы | только `--s1…--s6` (4/8/12/16/24/32). Экран — `gap: var(--s5)` (`.stack`), карточка — `padding: var(--s4)` и `gap: var(--s3)`, подписанный блок внутри карточки — `--s2` (`.block`). Своих `margin` у блоков нет: ритм задаёт родитель |
| Высоты | **только контрольная шкала**: `--control-sm` (32 — сегменты и тихие пилюли), `--control`/`--tap` (44 — любая подписанная кнопка и любое поле ввода), `--icon` (40 — любая квадратная кнопка-иконка), `--row` (56 — строка списка). Раньше в файле жили 32/34/36/38/40/48/52/54 — отсюда и бралась «разномастность» |
| Типографика | только `--t-xs…--t-3xl` (12/13/15/17/22/32/48) и два веса: `--w-normal` (500) и `--w-strong` (650) |
| Форма | `--radius` (12) у карточек и тоста, `--radius-sm` (8) у **каждого** элемента управления: кнопки, сегменты, чипы, дни недели, прибор `− значение +`. Полностью круглыми остались только полосы (метр дня, столбик графика, отметка дня) — пилюля 999px рядом с прямоугольными кнопками читалась как чужой элемент |
| Карточка | один паттерн: заголовок, подпись, содержимое; 16px внутри, 12px между детьми, без «пустых» наполовину блоков |
| Строка | **один** компонент `HabitRow` на все списки: галочка, название, одно действие. Никакой колонки значений в строке нет: привычка сделана или нет, и строка никогда не спрашивает «сколько?». Название тянется, действие прижато к правому краю (`--icon` = 40px) — поэтому у всех строк списка правый край совпадает |
| Настройки | строки, а не плашки: `Язык [Русский|English]` — подпись слева, маленький переключатель справа. Полноширинный сегмент на бинарный выбор был самым тяжёлым элементом в приложении |
| Иерархия | что вообще имеет право быть громким — см. таблицу ниже |
| Опасное | отдельный токен `--danger` и только для разрушительных действий (удалить данные, удалить привычку). Ни одно состояние привычки красным не красится |

Что имеет право быть громким:

| Роль | Чем показывается |
| --- | --- |
| Состояние привычки | **единственный синий** `--accent`: отмеченная галочка и главная кнопка шторки. На большинстве экранов синего нет вовсе |
| «Ты здесь» | нейтральная приподнятая пилюля `--pick` (`#3a3d47`): активная вкладка, выбранный язык и тема, выбранные дни недели в форме. Это навигация и настройки, а не состояние, поэтому синего тут нет |
| Сегодня | на статистике сегодняшний день отмечен синим **кольцом**, а не заливкой: заливка точки значит «был прогресс», и пустой сегодня не должен выглядеть закрытым |
| Границы | карточка читается тонкой светлой линией `--line` (`#33353c`), а не тяжёлой заливкой: `--surface-2` — всего один шаг над фоном. Сильная граница `--line-strong` — только у интерактивных элементов (кнопки, поля, пилюли) |
| Текст | два уровня: `--fg` для названий и значений, `--muted` для подписей. Длинных объяснений в интерфейсе нет: каждая фраза — это то, что человек читает вместо того, чтобы закрыть привычку |

Экран «Сегодня» — список галочек и ничего больше:

- Тап по строке = сделано, ещё тап = снято. У «не делать» галочки нет: срыв отмечается явной
  кнопкой `Ban`, чтобы случайное касание не портило серию. Больше в строке нет ничего: раньше здесь
  жили `− значение +`, «просто начни» и значение дня, и именно из-за них приложение казалось сложным.
- **Привычка больше не спрашивает «сколько».** Ни счётчиков, ни целей, ни минут, ни чипов быстрого
  ввода, ни таймера: если дело требует двадцати минут, это задача, а не привычка. В модели данных
  старые типы остались (`counter`, `duration`, `flex`), чтобы не потерять историю и бэкапы, но
  интерфейс их не создаёт: новая привычка — всегда галочка. Один тап закрывает и старую привычку
  с целью: `tapHabit` пишет сразу всю цель, поэтому «6 стаканов» отмечаются так же, как «выпить таблетки».
- Прошлое появляется **только когда оно важно**: если вчера было пусто, под заголовком появляется
  короткая фраза и ссылка «Открыть вчера» (`missedYesterday`). Полосы дней и листания недель больше
  нет — смотреть назад имеет смысл ровно затем, чтобы дозаполнить пропуск, а не гулять по пустой
  истории. Открытый прошлый день честно называется «Прошлый день», рядом есть «Вернуться к сегодня»,
  а привычки, которых в тот день ещё не было, не показываются (`habitsUpTo`).
- **Одна короткая фраза о дне** вместо уведомлений: «На сегодня всё.» когда день закрыт и
  «Вчера было пусто. Один пропуск прощается.» когда есть риск.
- **Действия, которые легко задеть случайно, оставляют путь назад**: срыв, удалённая мысль, привычка
  со старой целью — тост предлагает «Отменить». Все мутации чистые, поэтому отмена — это просто
  сохранённый `AppData` и `replace(before)`; отдельного журнала изменений не нужно. Тост с отменой
  живёт 5.2 с вместо 2.6 с — его надо успеть прочитать и нажать.
- Управление (изменить, порядок, закрепить, архив) живёт в шторке вкладки «Привычки»: там действия редкие,
  и им уместно иметь подписи — иконка + текст.
- Числа везде с `font-variant-numeric: tabular-nums`, чтобы счётчики не дёргали вёрстку.
- Вкладки адресуются хэшем (`/#stats`), поэтому состояние открывается по ссылке и снимается скриптом.

Статистика — **две цифры и семь точек**, и это всё. Раньше здесь были окна 30/90, переключатель
диапазона, легенда из четырёх образцов, полоса на тридцать дней и по тридцать столбиков на каждую
привычку: вкладка превращалась в дашборд, на который не хочется заходить, а «длинные непонятные
графики» не отвечали ни на один вопрос.

- Заголовок — такая же карточка, как остальные: серия («23 дня подряд») и лучшая серия за 90 дней.
  Лучшая считается на квартале, а не на неделе: за семь дней она всегда упирается в семь.
- **Эта неделя** — семь точек (`dayHeatStatus`), точка это день: была работа или нет. Сегодня
  отмечено синим кольцом, а не заливкой. Ниже одна строка: «Дней с делами: 5 из 7».
- **По привычкам** — строки одного списка: имя и серия. Всё. Проценты за окно, лучшие и худшие
  привычки, тон недели и вывод по дням недели убраны: это был текст, который читают вместо того,
  чтобы закрыть привычку.

Иконки — **Lucide** (`lucide-react`), 16 штук, ~3 КБ gzip в бандле. Свои рисованные SVG убраны:
самодельные `Play`, `±`, таймер и текстовый `✕` выглядели кустарно.

Настройки — четыре карточки вместо шести, и на всей вкладке **нет ни одного синего** (у настроек нет
главного действия, значит и акцента нет):

- «Интерфейс» — две строки: подпись слева, маленький переключатель справа. Раньше это были две
  полноширинные плашки по 44px на бинарный выбор — самый тяжёлый элемент в приложении. У обоих
  переключателей **одна ширина** (176px, половины равные): «Чёрная/Белая» ровно такой же ширины, как
  «Русский/English», иначе две строки одного смысла выглядят разными.
- «Данные» — две **одинаковые** кнопки (скачать / загрузить) во всю ширину карточки, строка состояния
  бэкапа и «Вставить JSON вручную», свёрнутая в строку списка с шевроном (56px, обычный разделитель
  сверху), а не висящая подчёркнутой ссылкой в пустоте.
- Все кнопки в карточках — одной ширины (во всю карточку). Узкая кнопка «Удалить все данные» рядом с
  широкими соседями читалась как случайно прилипшая.
- «Опасная зона» помечена **одним** красным — кнопкой. Красный заголовок над ней убран: три красных
  элемента подряд превращали редкое действие в тревогу.

Шторка (модалка, форма, быстрое окно) — колонка: заголовок и футер видны всегда, прокручивается только
тело (`overflow: hidden` у `.sheet`, `overflow-y: auto` у `.sheet-body`). Раньше футер уезжал под сгиб
на коротких экранах, и «Сохранить» в форме привычки приходилось искать прокруткой: форма открывалась,
а сохранить её было нельзя. Плюс у новой привычки курсор сразу стоит в поле названия.

Шрифт — **Manrope Variable** (`@fontsource-variable/manrope`), самохостинг с сабсетами cyrillic + latin:
39 КБ на первую загрузку, дальше из кэша service worker. Внешних запросов по-прежнему ноль.

## 💾 Модель данных

```ts
interface Habit {
  id: string;
  name: string;
  kind: 'check' | 'counter' | 'duration' | 'negative' | 'flex';
  target?: number;   // counter: цель в день, duration: целевые минуты
  unit?: string;     // «стаканов», «мин»
  perWeek?: number;  // flex: сколько раз в неделю
  step?: number;     // counter: шаг кнопок +/−
  days?: number[];   // дни недели, 0 = понедельник; нет поля — каждый день
  tiny?: string;     // версия привычки на 2 минуты для «просто начни»
  pinned?: boolean;  // показывать в «Главном сегодня» (максимум 3)
  archived?: boolean;
  createdAt: string; // ISO; дни раньше этой даты не считаются пропусками
  order: number;     // плотный порядок 0..n-1
}

interface Entry {
  value?: number;    // counter/duration — накопленное, negative — число срывов
  done?: boolean;    // check/flex — выполнено
  note?: string;
}

interface DayLog {
  entries: Record<string, Entry>; // ключ — id привычки
  dump: DumpItem[];               // брейн-дамп на этот день
}

interface AppData {
  version: number;
  habits: Habit[];
  days: Record<string, DayLog>;   // ключ — локальная дата YYYY-MM-DD
  settings: { lang: 'ru' | 'en'; theme: 'dark' | 'light' };
}
```

Принципы:

- **Дни адресуются локальной датой** (`YYYY-MM-DD` в таймзоне пользователя), а не UTC: «сегодня» должно совпадать с календарём на стене.
- **Пустое не хранится.** Снятие галочки удаляет запись, а день без записей и без мыслей удаляется целиком — база не пухнет от пустых объектов.
- **Хронология важна.** `createdAt` отделяет «привычки ещё не было» от «привычка пропущена»: до даты создания день имеет статус `rest` и не портит статистику.

## 🧠 Логика привычек

### Правила выполнения

| Тип | Выполнено когда | Значение по умолчанию |
| --- | --- | --- |
| `check` | есть запись с `done: true` | не выполнено |
| `negative` | `value === 0` — то есть срывов нет | **выполнено** (чисто по умолчанию) |
| `counter` | `value >= target` | не выполнено |
| `duration` | `value >= target` (минуты) | не выполнено |
| `flex` | есть запись с `done: true` | `rest` — день ничего не требует |

Первые два типа — то, что создаёт интерфейс. Остальные три остались в модели и в правилах выше,
чтобы **читать** старые данные и бэкапы: привычка с целью ведёт себя как галочка (один тап пишет
всю цель), а её `target`, `unit`, `perWeek` и `tiny` больше нигде не показываются. Отредактированная
через форму привычка становится `check` или `negative` — цель при этом исчезает, и это осознанный
выбор: приложение, которое спрашивает «сколько стаканов», и есть та сложность, от которой оно лечит.

### Статус дня

`dayStatus(data, habit, key)` возвращает одно из пяти значений:

| Статус | Когда |
| --- | --- |
| `future` | дата позже сегодня |
| `rest` | день раньше `createdAt`, день вне расписания, либо flex-привычка без записи |
| `done` | по правилам выше |
| `partial` | есть частичный прогресс: `0 < value < target` |
| `missed` | ничего не отмечено |

### Расписание

У привычки может быть список дней недели — `Habit.days`, `0` = понедельник. День вне списка становится
`rest`, а не пропуском: он не рвёт серию, не попадает в кольцо дня и в процент выполнения, а в
полосе-графике рисуется как «не требовалось». На экране «Сегодня» такая привычка не показывается —
вместо неё одна ссылка «Показать не по расписанию (1)», чтобы её всё-таки можно было отметить.

«Каждый день» хранится как **отсутствие поля**: пустой список и все семь дней нормализуются в `undefined`,
чтобы у самого частого случая не было состояния, которое можно рассогласовать. Гибкие привычки
(`flex`) живут по недельной цели и расписание игнорируют.

### Мягкие серии

Главная механика против срывов: один пропуск не обнуляет прогресс.

```
softStreak(habit):
  streak = 0; misses = 0
  идём назад от сегодняшнего дня до createdAt:
    rest / future            → пропускаем, ничего не меняем
    done                     → streak += 1; misses = 0
    missed / partial, i == 0 → сегодня ещё открыт, пропускаем
    missed / partial         → misses += 1; если misses >= 2 → стоп
  вернуть streak
```

То есть две пропущенные даты подряд ломают серию, одна — поглощается. `bestStreak()` прогоняет тот же автомат
по всей истории вперёд и запоминает максимум — так «лучшая серия» никогда не уменьшается.

### Агрегаты

| Функция | Что считает |
| --- | --- |
| `dayProgress` | кольцо дня: только «действенные» привычки (`check`, `counter`, `duration`) |
| `scheduledOn` | нужна ли привычка в этот день недели |
| `habitsUpTo` | привычки, которые уже существовали на эту дату: прошлое не требует того, чего ещё не было |
| `weekProgress` | прогресс flex-привычки за календарную неделю с понедельника |
| `completionRate` | доля выполненных дней за переданное окно (библиотечная функция: интерфейс её больше не зовёт) |
| `habitCounts` | сколько раз привычка закрыта и сколько раз её ждали (для гибких — недельная цель) |
| `weekReview` | итоги недели: живых дней, лидер и отстающий (библиотека; интерфейс показывает только счёт дней) |
| `weekdayRates` | доля закрытых привычек по дням недели: где именно проваливается (библиотека, из интерфейса убрано) |
| `missedYesterday` | сколько привычек пропущено вчера и всё ещё открыто сегодня |
| `dayHeatStatus` | статус всего дня для общей карты: `done` только если закрыты все |

`negative` и `flex` выведены из кольца дня намеренно: «не делать» не требует ежедневного действия,
а гибкая привычка измеряется неделей. Иначе прогресс показывал бы выполнение там, где ничего не делалось.

<a id="storage"></a>

## 🗄 Хранение и импорт

- Ключ в `localStorage`: **`deeptracker.v1`**, запись — на каждое изменение состояния (`store.tsx`).
- `loadData()` при отсутствии данных создаёт стартовый набор привычек на языке браузера.
- `normalizeData()` — защитный слой: незнакомый `kind` превращается в `check`, нечисловые цели отбрасываются, даты проверяются регуляркой, мусорные дни удаляются. Поэтому старый или руками правленный JSON не ломает приложение.
- `parseImport()` бросает ошибку на чужой JSON (например, без непустого массива `habits`) — интерфейс показывает понятный тост.
- `toJson()` / `downloadJson()` — бэкап файлом `deeptracker-YYYY-MM-DD.json`.
- **Дата последнего бэкапа** (`settings.lastExport`) пишется при экспорте и переживает экспорт/импорт. Данные живут только в этом браузере, поэтому экран настроек сам говорит, когда файл скачивали в последний раз, и напоминает, если прошло три недели или бэкапа не было вовсе. Это единственное напоминание в приложении, и оно появляется только когда есть что терять.

<a id="pwa"></a>

## 📴 PWA и офлайн

- `public/manifest.webmanifest` — standalone, `start_url: ./`, иконки `any` + `maskable`.
- `public/sw.js` — две стратегии:
  - **навигация** — network-first с фолбэком на кэш: свежий деплой подхватывается сразу, офлайн открывается последняя версия;
  - **остальное** — stale-while-revalidate: мгновенный ответ из кэша и тихое обновление в фоне.
- Service worker регистрируется **только в продакшн-сборке** и только по `http(s)` — с `file://` он невозможен, а в dev он мешал бы HMR.
- **Правило:** поменял оболочку (иконки, манифест, статику) — подними `CACHE_VERSION` в `public/sw.js`, иначе у установивших приложение останется старая закэшированная версия. Хэшированные ассеты и `index.html` обновляются сами.
- `public/.nojekyll` — чтобы GitHub Pages не пытался обрабатывать файлы через Jekyll.

<a id="scripts"></a>

## 🛠 Скрипты

| Команда | Что делает |
| --- | --- |
| `npm run dev` | dev-сервер на `127.0.0.1:5173` (явный IPv4 — см. [траблшутинг](deploy.md#troubleshooting)) |
| `npm run build` | `tsc --noEmit` + сборка в `dist/` |
| `npm run preview` | статический сервер продакшн-сборки на `127.0.0.1:4173` |
| `npm test` | прогон Vitest |
| `npm run typecheck` | только типы |
| `npm run icons` | перегенерировать `public/icons/*` и `public/og.png` |
| `npm run shots` | снять скриншоты всех экранов в `docs/screenshots` (нужен запущенный `npm run preview`) |

`scripts/make-icons.mjs` не тянет графических библиотек: PNG собирается вручную (IHDR/IDAT/IEND + CRC32
и `zlib.deflateSync`), а галочка рисуется суперсэмплингом 4×4 с премультиплицированным усреднением —
поэтому скруглённые углы и концы штриха получаются гладкими.

`scripts/shots.mjs` управляет headless Chrome по DevTools Protocol: подставляет демо-данные за 24 дня
init-скриптом (до гидратации приложения — иначе гонка), открывает вкладки по хэшу и сохраняет PNG.
Путь к браузеру — `CHROME_PATH`, адрес — `SHOTS_BASE`.

`scripts/smoke.mjs` проверяет, что сервер или деплой реально отдаёт всю статику и SEO-разметку:

```bash
node scripts/smoke.mjs                            # dev на :5173
node scripts/smoke.mjs http://127.0.0.1:4173/     # локальный preview
node scripts/smoke.mjs https://<user>.github.io/<repo>/   # живой деплой
```

Скрипт сам определяет режим (dev или продакшн-сборка), качает `index.html`, точку входа или хэшированный
бандл, манифест, service worker, favicon, иконки, `robots.txt`, `sitemap.xml`, `og.png`, проверяет
`<title>`, `description`, `canonical`, Open Graph, Twitter-card и JSON-LD, и падает с ненулевым кодом,
если чего-то не хватает.

<a id="build"></a>

## 📦 Сборка

| Параметр | Значение |
| --- | --- |
| `base` | `'./'` — относительные пути, один и тот же `dist/` работает на project- и user-страницах Pages и на своём домене |
| `target` | `es2019` |
| JS | ~270 kB raw / **~84 kB gzip** (включая ~3 КБ иконок Lucide) |
| CSS | ~19 kB raw / **~6.5 kB gzip** |
| Шрифт | `assets/manrope-*-wght-normal.woff2`, 5 сабсетов ~72 КБ в сборке; браузер скачивает только cyrillic + latin (~39 КБ) |
| Артефакты | `index.html`, `assets/*`, плюс всё из `public/`: манифест, `sw.js`, `robots.txt`, `sitemap.xml`, `og.png`, иконки |

Внешних CDN и запросов наружу нет — шрифт самохостится из бандла, поэтому приложение работает офлайн.

<a id="i18n"></a>

## 🌍 Локализация

Словари в `src/lib/i18n.ts`. `ru` — источник истины: тип `Dict` выводится из него, поэтому забытый или
опечатанный ключ в `en` ломает `npm run typecheck`, а не доезжает до продакшена. Подстановки — через `fill()`
(`{done} из {total}`). Стартовый набор привычек тоже локализован (`SEED_HABITS`).

Добавить язык: скопировать объект `en`, перевести, добавить в `STRINGS` и в тип `Lang`.
